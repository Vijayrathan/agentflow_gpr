# 1. Introduction

## 1.a Motivation

Subsurface assessment underpins a wide range of applications, from soil-moisture and root-zone monitoring in precision agriculture to buried-object detection, infrastructure inspection, and hydrological characterization [Ref: Romero-Ruiz_2018; ReviewpapersoilmistureV5-2; AComprehensiveReviewofGroundPenetrating]. Among the available geophysical tools, Ground-Penetrating Radar (GPR) offers a compelling combination of resolution and non-invasiveness, and recent drone-borne GPR platforms extend this capability to high-speed, large-area, and otherwise inaccessible surveys [Ref: Unmanned_Aerial_Vehicle-Based_GPR_A_review; Buried_Object_Imaging_Using_a_Small_UAS; A_drone_carried_multichannel_SAR; Analysis_of_Low-Frequency_Drone-Borne_GPR]. To unlock the full value of these platforms, the community is increasingly coupling GPR hardware with machine-learning (ML) pipelines for clutter removal, target detection, and full-waveform inversion — i.e., *intelligent* GPR [Ref: Declutter-GAN; Giannakis_ML_Fast-Forward_Solver; Full-wave_inversion_using_deep_learning; Advanced_Machine_Learning]. These models, however, are notoriously data-hungry, and field campaigns to collect labeled GPR data are expensive, slow, and constrained by site access and ground-truth availability. Realistic synthetic data generation is therefore a critical enabler. Open finite-difference time-domain solvers such as gprMax [Ref: Input_file_commands_gprMax; Scripting_the_input_file_gprMax; Target_Detection_GPRMAX] make this possible in principle, but in practice they require simultaneous fluency in electromagnetics, soil physics, antenna and waveform design, and the solver's own scripting interface — a barrier that excludes most domain users. A conversational interface that lowers this barrier is needed.

## 1.b Prior Art

Prior efforts relevant to this work cluster into three threads, each leaving the bottleneck we target unresolved. First, *open simulation tooling* — chiefly the gprMax FDTD solver — supports heterogeneous soils, fractal surfaces, and arbitrary antenna/waveform definitions [Ref: Input_file_commands_gprMax; Scripting_the_input_file_gprMax], yet every dataset campaign still begins with hand-written `.in` scripts and ad-hoc Python parameter sweeps that are reinvented per project and seldom shared. Second, *ML-driven GPR pipelines* — including GAN-based B-scan clutter removal, learned fast-forward solvers, and deep full-waveform inversion — explicitly rely on gprMax-generated synthetic data to offset scarce field measurements [Ref: Declutter-GAN; Giannakis_ML_Fast-Forward_Solver; Full-wave_inversion_using_deep_learning; Target_Detection_GPRMAX; Advanced_Machine_Learning]; the resulting corpora, however, are bespoke, narrow in scenario coverage, and tied to private codebases, which limits reuse and cross-study benchmarking. Third, *LLM-backed scientific assistants* have shown value for literature search, code generation, and tutoring, but published systems typically operate as a single dialogue agent over a single retrieval corpus and target software-only workflows that do not couple to physical validation. To our knowledge, no prior system orchestrates multi-domain parameter elicitation, physics-aware script synthesis for an FDTD solver, batch simulation execution with automatic error recovery, and shared dataset curation within a single conversational pipeline.

## 1.c Proposed System

We present **[SYSTEM NAME]**, a conversational interface that opens drone-borne GPR data generation to users from across geophysics, ECE, soil science, and machine learning. Our goal is to collapse the multi-step, multi-expertise workflow that gprMax demands today — soil-layer specification, antenna and waveform design, electromagnetic-mesh sizing, batch scripting, simulation execution, and post-hoc validation — into a single guided dialogue, without sacrificing the physical rigor those steps require.

[SYSTEM NAME] is built on two cooperating layers. A **multi-agent orchestration layer** decomposes the workflow across specialized agents for parameter elicitation, dataset generation, and simulation control, each enforcing schema and physics constraints on its slice of the problem. A **retrieval-augmented knowledge base** over 58 curated GPR and soil-physics references grounds every agent's reasoning in published dielectric models, gprMax syntax, and UAV-GPR design practice rather than generic LLM priors. Together, these layers enable users to (i) describe a subsurface scenario in natural language and obtain a validated batch of gprMax `.in` files; (ii) execute simulations with automatic error recovery and GPU acceleration; (iii) persist generated datasets and parameter ranges in a relational store and reuse data contributed by other users through the same chat interface; (iv) ingest and tag field-collected data alongside synthetic counterparts; (v) visualize the configured subsurface geometry and antenna placement; (vi) attach and test ML models on curated datasets; and (vii) pull complementary observations from external sources such as the International Soil Moisture Network (ISMN).

## 1.d Contributions

The technical contributions of this paper are as follows.

**(1) A multi-agent orchestration framework for gprMax workflows.** We design a pipeline of seven specialized agents — covering soil-layer extraction, antenna and waveform configuration, simulation-domain specification, advanced geometry (buried objects, fractal surfaces, receiver arrays), batch dataset generation, simulation execution, and error rectification — implemented on top of LangGraph and the DeepAgents pattern. The agents communicate through a checkpointed state graph and a shared parameter-state service, and each top-level agent is internally decomposed into a *Knowledge / Validation / Master* sub-agent triad that cleanly separates geophysical reasoning, schema enforcement, and control flow.

**(2) A geophysics-grounded RAG knowledge base as the system's backbone.** The agents are not bare LLMs; every parameter-elicitation turn is grounded in a curated corpus of 58 GPR and soil-physics references (e.g., Peplinski, Dobson, and Mironov dielectric models; gprMax documentation; UAV-GPR systems). The corpus is ingested with layout-aware parsing (MinerU) and semantic chunking, indexed in Qdrant with hybrid *dense (BGE-M3) + sparse-lexical* vectors, and re-ranked with `bge-reranker-v2-m3`, with a relevance threshold that suppresses low-quality retrievals.

**(3) A physics-aware code-generation and sampling pipeline.** Pydantic-validated parameter ranges are translated into gprMax `.in` files through accept–reject sampling for soil texture, mixture-model dielectric computation across CRIM, Peplinski, Dobson, and Mironov formulations, and thirteen LangChain validation tools that enforce PML clearance, wavelength-based mesh resolution, frequency-band feasibility per dielectric model, antenna offsets, and domain–layer z-alignment.

**(4) A self-correcting simulation loop.** A Simulation Agent parses gprMax runtime errors and a Rectifier Agent applies targeted fixes to the offending `.in` file or parameter set, enabling unattended, GPU-accelerated batch execution at dataset scale.

**(5) A persistence, versioning, and access layer.** Extraction sessions, simulation runs, and post-processed signals are persisted in PostgreSQL via SQLModel with Alembic migrations; the knowledge-base snapshots are version-controlled with DVC; and the entire system is delivered to users through a FastAPI WebSocket backend and a React/TypeScript chat interface.

**(6) An empirical validation protocol.** We combine a physics-audit test suite — covering Debye decomposition, bandwidth derivation, axis conventions, and fractal-geometry generation — with end-to-end workflow checks for script-generation accuracy, simulation reproducibility, and retrieval relevance.
